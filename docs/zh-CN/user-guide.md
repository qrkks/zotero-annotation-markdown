# 使用指南

[English](../en/user-guide.md)

## 支持的行为

- PDF 和 EPUB 阅读器侧栏里的标注评论默认按 Markdown 渲染。
- LaTeX 数学公式默认启用，支持 `$...$`、`$$...$$`、`\(...\)` 和 `\[...\]` 分隔符。
- 单个换行会保留为可见换行。
- 裸 URL 会在渲染预览中自动变成可点击链接。
- 使用 `==双等号==` 包裹的文字会渲染为高亮；可通过颜色后缀选择安全的预设颜色。
- 编辑时在快速编辑器中显示原始 Markdown 源码，失焦或按 Esc 即保存。
- 不信任原始 HTML，渲染结果会经过清理。
- Markdown 渲染失败时保留原始纯文本。

### SVG 示意图（实验性）

在设置中开启 **Render SVG code blocks (Experimental)**，即可预览 fenced `svg` 代码块中的静态图。默认关闭；开启侧栏或页内弹窗 Markdown 渲染后可用。切换会刷新已打开的 Reader。Zotero 仍保存原始 Markdown 和 SVG 文本，不会创建附件，也不依赖外部图片服务。

复制 AI 的整段回复时，图示可能位于没有语言标记的代码块中。只要整个代码块是一份完整 SVG 文档，也会自动识别；可包含外围空白、XML 声明和注释。仍由同一个 SVG 开关控制，并遵守相同限制。普通代码、不完整片段，以及明确标记为 `xml`、`html`、`text` 等其他语言的代码块继续显示源码。想展示 SVG 源码时，可使用这些语言标记。

~~~~markdown
```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 320 100">
  <rect x="10" y="10" width="300" height="80" rx="8" fill="#eff6ff"/>
  <text x="160" y="56" text-anchor="middle" font-size="18" fill="#1e293b">示意图</text>
</svg>
```
~~~~

图片适配预览宽度。**View larger** 在可滚动的浮层中按原始尺寸查看同一张清洗后的图片；可通过 **Close**、Escape 或点击遮罩关闭。Tab 保持在浮层内。普通点击图片仍沿用现有源码编辑流程。

支持基本图形、路径（包括紧凑坐标写法）、分组、文字/tspan、局部箭头标记、局部线性/径向渐变及受限的内嵌 WOFF2 字体。请用 `fill`、`stroke`、`font-size` 等属性设置外观。文字/tspan 还可使用 `style="white-space: pre;"`，并支持 `direction="ltr"` 或 `direction="rtl"`。暂不支持一般 CSS/style 属性、嵌入 HTML、外部资源、`use`、动画、滤镜、非空遮罩、文档声明和其他命名空间。SVG 标签中的文字按字面显示；LaTeX 仅在外围 Markdown 中渲染。图中文字不能像 Markdown 文本一样直接选择。

对基本的 AI 和绘图工具导出，预览可以忽略根元素的 `version` 属性、仅含 `max-width:100%` 的根元素样式、空元数据/样式表，以及未被引用的空遮罩。复制产生的不换行空格只在标签语法中规范化，文字和引号内的属性值保持原样。这些调整只作用于预览，不改动保存的源码。这属于有限的导出兼容，并不代表支持所有 Excalidraw 导出。此 MVP 中，代码围栏外的裸 SVG 仍显示为文本。

内嵌字体要求样式表只包含 `@font-face`，使用简单的 `font-family` 和单个 `src: url(data:font/woff2;base64,...)`；可选 `format("woff2")`、基本 `font-weight` 和 `font-style` 声明。每张 SVG 最多 4 个字体，单个解码后的字体数据不超过 8 KiB，合计不超过 16 KiB。仅支持不带附加元数据/私有数据块的单字体 WOFF2 文件。字体只保留在 SVG 图片内部，不会安装或注册到 Reader。不支持的字体声明、一般 CSS 或超出限制的字体会说明原因并显示原始源码。

每个代码块限制为 32,000 个源码字符、512 个元素、32 层嵌套，图片及 viewBox 尺寸不超过 4096 × 4096。需要 viewBox 或数值形式的宽高。格式错误、不支持的内容或超出限制时显示简短原因和转义后的代码块；图片加载失败也会显示源码。向 AI 请求图示时，可要求：输出到 `svg` 代码块，包含 viewBox，使用基本图形与文字，通过属性设置样式，不引用外部资源。

### 高亮颜色

使用 `==文字==` 显示默认黄色高亮。在结束的 `==` 后面紧接一个受支持的颜色后缀，即可选择其他预设颜色：

```markdown
==默认黄色==
==风险提示=={.red}
==重点内容=={.orange}
==确认结论=={.green}
==补充信息=={.blue}
==个人观点=={.purple}
==次要内容=={.gray}
```

支持的后缀为 `.yellow`、`.red`、`.orange`、`.green`、`.blue`、`.purple` 和 `.gray`。任意类名、多个类名、样式属性和自定义颜色值都不会被解释；未知或未紧接高亮的后缀会作为普通文字保留。

## 安装

推荐在 Zotero 插件市场中搜索 `Zotero Annotation Markdown` 并安装。

也可以从[最新 GitHub Release](https://github.com/qrkks/zotero-annotation-markdown/releases/latest)下载 `zotero-annotation-markdown.xpi`。在 Zotero 中打开 **工具 → 插件**，然后把 `.xpi` 文件拖入插件窗口。

## 设置

打开 Zotero 设置并选择 **Annotation Markdown** 面板。当前设置包括：

- 是否渲染侧边栏标注评论中的 Markdown；
- 是否在页内标注弹窗中渲染 Markdown；默认关闭；
- 是否把剪贴板内容以纯文本形式粘贴到评论中；推荐在粘贴 AI 回复时启用，使 Markdown 保持可编辑，并避免带入富文本格式或隐藏 HTML；
- 是否使用快速评论编辑器；该功能默认开启，也可以关闭并恢复 Zotero 原生编辑器；
- 是否渲染 LaTeX 数学公式；
- 选择公式渲染方式：默认使用标准渲染，也可选择实验性的原生 MathML；
- 是否为包含多个标题的标注显示浮动大纲；该功能默认开启；
- 单独将浮动大纲文字大小调整为 80% 到 200%；100% 保持原有大小；
- 是否在标注评论出现 `todo:`、`todo：`、`t:` 或 `t：` 指令时自动给该标注添加 `todo` 标签；默认关闭；
- 是否在移除指令并保存评论后自动清理该标注的小写 `todo` 标签；默认关闭，须先开启自动添加；
- 把预览字号调整为 80% 到 200%；
- 选择标注渲染策略；
- 是否实验性加速超大标注列表取消标签筛选后的恢复；默认关闭。

**Reader Annotations** 分组中的 **Math rendering** 提供 **KaTeX HTML + MathML (default)** 和 **Native MathML only (Experimental)** 两种模式。默认模式由 KaTeX HTML 负责公式的可视排版，并附带供辅助阅读使用的 MathML。原生 MathML 可以降低公式较多的标注的渲染开销，使用 Zotero 原生数学排版，因此公式间距、高度和字体外观可能有所不同。该选项已在 Windows 上的 Zotero 10.0.5 和 10.0.6 中验证。切换后会立即刷新已打开的 Reader，并保留保存的 LaTeX 源码；随时选择 **KaTeX HTML + MathML (default)** 即可切回。公式渲染是 Markdown 预览的一部分。侧栏和弹窗渲染都关闭时，公式开关与输出方式选择框会置灰，但保留已有选择。重新开启任一渲染后，公式开关恢复可用；输出方式选择框还需要开启公式渲染。

渲染策略包括：

- **自动（推荐）：** 较小的标注集合会提前渲染，较大的标注集合采用视窗懒加载。
- **渲染全部标注：** 调度所有标注预览进行渲染。
- **仅渲染视窗附近：** 标注接近侧栏可见区域时才进行渲染。

**Accelerate clearing tag filters in very large annotation lists (Experimental)** 当前只会在已经验证的 Zotero 10.0.3 Reader 结构中启用。请在完整标注列表加载后、选择标签筛选前开启此选项。加速需要至少 100 个未选中原生标注行的精确高度缓存，插件会在列表收窄前记录这些高度。随后取消已选标签时，远处标注可以先恢复为等高占位，并在接近视窗或被选中时创建完整原生行。该功能不会加速 Reader 首次打开；高度数据缺失、Zotero 版本不受支持或 Reader 结构不兼容时会自动沿用 Zotero 原生列表。关闭该选项后，占位行会分成小批次异步恢复为原生行。

设置会自动保存。Markdown 预览字号位于 **Reader Annotations** 分组中，紧邻渲染选项。如果阅读器没有反映新的设置，可以关闭并重新打开该阅读器，或重启 Zotero。

## 预览与编辑状态

**Render sidebar annotation comments as Markdown** 与 **Render page annotation popups as Markdown** 是两个平级开关，可以只开其中一项，也可以同时开启或关闭。侧栏渲染默认开启，弹窗渲染默认关闭；两项分别保留已有的勾选状态。预览字号、LaTeX 设置和公式输出方式由两者共用。渲染策略只控制侧栏评论，开启弹窗渲染后弹窗会即时处理。

标注未处于编辑状态时，评论显示为渲染后的预览。默认点击侧栏评论后会使用更快的源码编辑器；失焦或按 Esc 时保存修改。关闭 **Use the fast annotation comment editor** 后会恢复 Zotero 原生侧栏编辑路径。侧栏标注折叠时仍沿用 Zotero 的紧凑显示方式。

开启 **Render page annotation popups as Markdown** 后，页内标注弹窗会把评论渲染为 Markdown。该选项由独立开关控制，默认关闭。关闭时，弹窗的尺寸、定位、显示和预览渲染保持原生行为。快速编辑由 **Use the fast annotation comment editor** 独立控制：新打开的空弹窗会在 Zotero 布局稳定后直接进入快速文本框，已有弹窗内容则在点击后按需进入。文本框会在失焦或按 Esc 时只保存一次；关闭快速编辑或缺少 Reader 更新能力时，保留 Zotero 原生弹窗编辑器。开启 Markdown 弹窗渲染后，弹窗采用稳定的较宽宽度，并在较窄的 Reader 窗口中自动收缩；预览增加了舒适的内边距。长评论会在受视口限制的区域内纵向滚动，不会被裁掉，拖动或点击滚动条也会保持预览状态。当前批注的预览完成渲染并且布局稳定之前，弹窗保持透明。首次打开和切换批注时，弹窗都会等待新内容完成渲染，再按当前标注位置和最终尺寸定位，避免长公式渲染后再次跳动。空评论自动进入快速编辑器时，也会等文本框尺寸稳定后再显示。

如果当前 Zotero 版本没有提供快速编辑器所需的阅读器标注更新能力，插件会自动让 Zotero 原生编辑器继续接管。

插件不会用生成的 HTML 替换 Zotero 保存的 Markdown 源码。

启用自动 `todo` 标签后，标注评论中只要有一行以 `todo:`、`todo：`、`t:` 或 `t：` 开头（可缩进，不区分大小写，如 `TODO:`、`T：`），新建标注或修改评论并保存时就会给该标注添加小写 `todo` 标签。`t:` 是 `todo:` 的简写，也遵循相同的自动清理规则。已有 `todo` 标签（无论大小写）不会重复添加。该规则不扫描历史标注。

上述两个开关位于设置面板的 **Annotation Tags** 分组。可另外开启自动清理：修改并保存评论时，如果原评论有上述指令、新评论没有，就移除该标注的小写 `todo` 标签。只修改标签或编辑从未含有指令的评论不触发清理。Zotero 无法从同名标签判断是否由插件添加；此选项也可能清理手工添加的小写 `todo`，但不会清理大写 `TODO`。两个开关默认都关闭。

## 浮动大纲

当前选中的标注包含至少两个 Markdown 标题时，一个紧凑的**大纲**按钮会固定在标注侧栏视口旁边，所以长标注开头滚出视野后仍能使用。它优先放在侧栏滚动条右侧的空白区域；窗口较窄时则移到内侧并向左展开。大纲收录 `H1` 至 `H6`，保留标题层级，并高亮标注侧栏顶部附近的当前章节。点击条目只会在标注侧栏内平滑滚动到对应标题，不会进入评论编辑或改变当前选中的标注。

浮动大纲默认启用，可在 **Floating Outline** 设置分组中通过 **Show a floating outline for annotations with multiple headings** 关闭。**Outline font size** 可在 80% 到 200% 之间调整，100% 保持原有大小；它与 Markdown 预览字号独立，调整后会立即更新已打开的 Reader。文字放大时，空间允许的情况下大纲面板也会相应变宽。新安装默认收起大纲；用户主动展开或收起后，该状态会独立保留在不同标注、Reader 标签页及 Zotero 重启之间，因此关闭功能再重新开启也不会覆盖原有选择。少于两个标题的标注不显示大纲；进入评论编辑时只是暂时隐藏，渲染预览恢复后继续采用之前记住的状态。

## 侧栏定位

从侧栏或文档页面选择标注时，使用 Zotero 原生平滑滚动。单条选中标注高于侧栏视口时，无论向前还是向后切换，都会把开头定位到顶部附近，保留 2px 间距。短标注沿用原生定位。手动滚动不会自动回到选中的标注。

按 **Esc** 会保存并退出快速编辑。预览恢复后，只要标注还有一部分可见，就保持当前位置，不回到开头；只有整条标注都在视口外时，才在侧栏可滚动范围内平滑滚动一次，定位到同样的顶部 2px 位置。新的滚动、点击、输入、焦点变化或切换选中标注会取消待执行的定位补救。

点击其他位置也会保存，但普通失焦不会把上一条标注拉回视窗，方便继续操作另一条标注、文档页面或其他控件。

## 为什么替代编辑器可以更快

在真实阅读器的对比中，一本重度标注书籍的侧栏积累大量标注行和标签后，编辑会逐渐变慢。关闭替代编辑器会重新出现明显延迟，开启后输入又恢复流畅。这说明该工作负载下的主要延迟位于 Zotero 原生编辑路径，但不能据此断言只有标签数量是原因，也不能把问题归结到某一个尚未确认的 Zotero 内部函数。

Zotero 原生评论编辑器需要参与宿主管理的选中状态、焦点、编辑器组件状态和侧栏布局。周围侧栏越大、结构越复杂，这些工作就越可能变得昂贵。本插件避免让每次按键都进入这套原生编辑 UI：

1. 只为当前评论挂载一个轻量文本框，并保持周围标注预览连接不变。
2. 输入期间暂停插件自己的 Markdown 渲染工作，并把编辑器键盘事件限制在文本框内。
3. 失焦或按 Escape 时，通过 Zotero 的标注管理器一次性提交最终 Markdown 源码。
4. 保存后只刷新刚刚编辑的评论，并尽量保持侧栏中的可见位置。

插件不会建立另一套评论数据库，也不会绕过 Zotero 保存标注的数据模型。缺少必要的保存能力或用户关闭该偏好设置时，仍由 Zotero 原生编辑器接管。

## 兼容性

当前实现声明支持 Zotero Desktop 9.0 和 10.0.x。本版优先验证最新版 Zotero 10；Zotero 9 按尽力兼容原则保留支持，快速编辑集成不可用时可以回退原生编辑器。

阅读器侧栏 DOM 不是完全稳定的公开 API。即使自动化测试通过，Zotero 更新后仍应重新进行真实环境验证。
