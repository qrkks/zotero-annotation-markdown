# Static SVG MVP validation — 2026-10-10

The five examples supplied in issue #3 and the Chinese Jordan example passed real Zotero 10.0.6 / Gecko 140 validation on Windows. Implementation commit: `ff9f219`. This is a local experimental build, with SVG off by default; the published 0.12.3 package predates this feature.

[Copyable samples and manual checklist](../examples/svg-samples.md) · [Saved measurements](2026-10-10-svg-mvp.json) · [Supported subset](../en/user-guide.md#svg-diagrams-experimental)

## Persistence and reproduction

- Canonical source: [the five original issue samples](../../tests/fixtures/issue-3-svg-samples.md) and [Jordan SVG](../../tests/fixtures/jordan.svg).
- Automated regressions: [SVG rendering and lifecycle](../../tests/svg-rendering.test.js), [export compatibility](../../tests/svg-compatibility.test.js), and [restricted fonts](../../tests/svg-fonts.test.js). These run in `pnpm test` and the normal verification pipeline.
- Six dedicated SVG annotations remain on page 4 of the maintainer's development PDF, tagged `fixture::svg`. Its original seven Markdown/math/editor fixtures remain unchanged. A database readback confirmed the six annotations were still saved after manual testing.
- Other users can create note annotations on any PDF and paste one complete copy block from the sample guide. The examples do not require access to the maintainer's library or test PDF.
- The public guide is generated from the canonical fixtures with `node scripts/svg-samples.mjs`. `pnpm run docs:check` checks that it has not drifted from those fixtures; its copy blocks preserve the inner SVG fences and the original font data and NBSP characters.

Run the SVG regressions with:

```powershell
pnpm exec vitest run tests/svg-rendering.test.js tests/svg-compatibility.test.js tests/svg-fonts.test.js
pnpm run docs:check
```

## Fallback and viewer checks

Remote fonts, general CSS, a corrupt WOFF2 header, an oversized font, and an SVG script all fell back to the exact escaped source with an error. No preview images or live SVG/style/script nodes were created for these cases, and the script did not execute. This covers the listed cases; WOFF2 checks are bounded syntax, data size and basic header validation, with font tables validated by the browser.

The larger-image viewer uses the same sanitized image in a child browsing context. Native-host checks verified decoding, small-image fit, Tab focus containment, Escape closure, restored opener focus, unchanged selection, and no annotation deletion. Its tested keys did not reach the native Reader keyboard observer. Regression tests cover a native capture listener registered before the plugin and Gecko replacing the initial blank frame document. Sidebar and page-popup viewer paths were checked in the real host.

## Validation scope

The full verification pipeline passed 30 files / 571 tests, TypeScript, bilingual documentation, build and packaging before the final viewer height adjustment. After that adjustment, the 61 rendering/viewer tests, typecheck and packaging passed, followed by real-host viewer checks. The maintainer also reported no problems during manual testing on 2026-10-10; a detailed checklist for that manual run was not recorded.

When committing the public samples and this report, all three SVG regression files were rerun together: 147 tests passed. The documentation check passed, including generated-sample consistency and links from the sample guide.

MCP checks use native host APIs and untrusted synthetic DOM events. The instrumented reopen test closes and reopens the Reader, not the Zotero process. Actual clipboard, pointer and keyboard behavior, process restart, other Zotero versions and long-running use remain useful items for volunteer testing. Earlier test phases recorded native focus/toolbar and startup/network errors, so this record does not claim a clean console.
